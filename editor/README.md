# Редактор базы знаний

Отдельное React-приложение для правки сайта. Работает локально и пишет прямо в файлы сайта:
статьи — `../src/content`, разделы и главная — `../src/config.js`, картинки — `../public/images`.

## Запуск

```bash
cd editor
npm install      # один раз
npm run dev      # откроется http://localhost:5174
```

Или из папки сайта: `npm run editor`.

На Windows можно просто дважды щёлкнуть [`start.cmd`](start.cmd) (или ярлык на него): при первом запуске он сам установит зависимости, а если редактор уже запущен — только откроет его в браузере. Иконка для ярлыка — `icon.ico`.

## На другом компьютере

1. Установите [Node.js](https://nodejs.org) (LTS, версия 22 или новее) и [Git для Windows](https://git-scm.com).
2. Скопируйте папку проекта целиком — вместе со скрытой папкой `.git`, без неё публикация не заработает. Или: `git clone https://github.com/alex-listochek/wizards-mc.git`.
3. Дважды щёлкните `editor/create-shortcut.cmd` — появится ярлык «Редактор Wizards» с путями этого компьютера (старый ярлык помнит прежний путь и не откроется).
4. Запустите редактор ярлыком. При первом запуске он сам установит нужное (нужен интернет, около минуты).
5. При первой публикации Git попросит войти в GitHub — откроется окно браузера.

При каждом запуске редактор подтягивает с GitHub правки, опубликованные с другого компьютера. Несохранённые правки хранятся в браузере и между компьютерами не переносятся — перед переходом на другой компьютер сохраните и опубликуйте их. Если одну и ту же статью всё же поменяли на обоих компьютерах в одном месте, окно публикации покажет её и предложит оставить вашу версию.

После обновления кода редактора его нужно перезапустить (закрыть окно редактора и открыть ярлык снова).

## Публикация

Кнопка **«Опубликовать»** стоит рядом с «Сохранить». Цифра на ней — сколько сохранённых изменений ещё не на сайте. Окно публикации покажет, что уйдёт на сайт, сохранит несохранённые правки статей («Сохранить и опубликовать») и отправит всё на GitHub (`git add -A`, `commit`, `push`).

Где сейчас правки статьи, видно по метке рядом с её названием: «не сохранено» → «не опубликовано» → «опубликовано». В меню слева несохранённые статьи отмечены оранжевой точкой, а сохранённые, но ещё не опубликованные — пустым кружком. Дальше GitHub сам соберёт сайт, а редактор следит за сборкой и сообщит, когда сайт и Telegram Mini App обновятся (обычно 1–2 минуты).

Если на GitHub есть правки, которых нет на этом компьютере (например, файл поменяли на github.com), редактор сначала подтянет их, а потом отправит свои.

Пока локальный сайт (`npm run dev`) не запущен, ссылки «На сайте» ведут на опубликованный сайт — адрес берётся из `siteUrl` в `src/config.js`.

Чтобы видеть результат на сайте, запустите рядом и сам сайт (`npm run dev` в папке сайта, http://localhost:5173):
после сохранения он обновится сам. Адрес сайта можно поменять внизу меню редактора.

## Что умеет

- **Статьи**: создание, правка, переименование и перенос в другой раздел (ссылки на статью в других статьях и в настройках обновятся сами), удаление в корзину.
- **Редактор** с подсветкой Markdown, панелью инструментов и живым превью, которое рисуется тем же кодом и стилями, что и сайт. Превью можно смотреть «как на компьютере» и «как на телефоне».
- **Особая разметка сайта** одной кнопкой: плашки `[!NOTE]`/`[!TIP]`/`[!WARNING]`/`[!DANGER]`, цвета Minecraft `&b`, метка наказания, таблицы, команды.
- **Ссылки на статьи**: выбор статьи и заголовка из списка, подсказки при наборе `](#/`, проверка битых ссылок с кнопкой «Исправить».
- **Картинки**: вставьте из буфера (Ctrl+V) или перетащите в текст — файл сохранится в `public/images`.
- **Свойства статьи**: заголовок, описание, теги, дата обновления, порядок. Порядок статей меняется перетаскиванием в меню.
- **Разделы и главная страница**: названия, иконки, порядок разделов, адреса сервера, ссылки сообщества. В `config.js` меняются только изменённые значения, комментарии остаются.
- **Видно, что изменено**: строки, изменённые после сохранения, отмечены полосой слева от текста, место удалённого текста — красным уголком. Клик по метке «не сохранено» показывает все правки; любую можно «Вернуть как было» по отдельности или отменить все сразу.
- **Без потерь**: несохранённые правки переживают перезагрузку страницы; каждое сохранение откладывает прежнюю версию в `editor/.history` (по 50 на статью, с просмотром изменений и возвратом); удалённые статьи лежат в `editor/.trash`.
- **Правки из других программ** (VS Code, Блокнот) подхватываются сразу. Если файл изменили, пока в редакторе были несохранённые правки, редактор покажет обе версии и предложит выбрать.
- **Поиск** по названиям и тексту всех статей — Ctrl+P.
- **Ссылка для Telegram**: меню «⋯» у статьи → «Скопировать ссылку для Telegram» — ссылка вида `https://t.me/<бот>?startapp=раздел_статья` откроет статью прямо в Mini App. Бот указывается на странице «Главная страница».
- **Больше места для текста**: свойства статьи свёрнуты в одну строку, меню слева сворачивается в полоску с иконками (кнопка рядом с переключателем темы).

## Клавиши

| Клавиши | Действие |
|---|---|
| Ctrl+S | Сохранить статью |
| Ctrl+B / Ctrl+I | Жирный / курсив |
| Ctrl+K | Ссылка |
| Ctrl+Shift+K | Ссылка на статью |
| Ctrl+F | Найти и заменить в статье |
| Ctrl+P | Поиск по всем статьям |
| Alt+N | Новая статья |

## Как устроено

- `server/api.js` — локальный API внутри dev-сервера Vite: чтение и запись файлов, история, корзина, загрузка картинок, слежение за изменениями. Принимает запросы только от самого редактора.
- `server/jsconfig.js` — точечная правка `src/config.js`.
- `src/lib/frontmatter.js` — разбор и сборка шапки статьи по тем же правилам, что у сайта; неизменённые строки шапки не трогаются.
- Превью использует `../src/lib/markdown.js` и `../src/styles.css` сайта, поэтому всегда совпадает с сайтом.
